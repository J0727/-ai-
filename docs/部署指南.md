# 智汇研途 · 部署指南（Oracle Cloud 永久免费版）

> 目标：把系统部署到一台**永久免费**的公网服务器，拿到一个可演示的在线地址，并把数据自动备份到**免费对象存储**。

> 3. **券不能买域名**：300 元券不抵扣域名注册/续费。演示不需要域名，直接用 `http://公网IP:8000` 就行（想好看点再单独花几十元买域名，或挂 Cloudflare 免费 CDN）。

放行端口（轻量应用服务器是独立的「防火墙」页签，不是 ECS 那种安全组）：

> 控制台 → 轻量应用服务器 → 你的实例 → **防火墙** → 添加规则：`TCP 8000`、`TCP 80`、`TCP 443`

> ⚠️ **内地机器不要直接开 80/443 给公网**：内地服务器未备案的站点用 80 端口对外提供服务会被拦。本项目监听 **8000**，用 `http://公网IP:8000` 访问**不需要备案**，演示直接用这个地址；自己配域名指向 80 才需要备案。

#### 阿里云实战踩坑记录（2026.11，上海轻量 2C2G 实测）

| 现象 | 原因 | 现在的解法 |
| ---- | ---- | ---- |
| `curl get.docker.com` 报 `Connection reset by peer` | 内地访问 Docker 官方脚本被 TLS 重置 | `bootstrap.sh` 改走 `mirrors.aliyun.com/docker-ce` |
| 构建停在 `apt-get install` 十几分钟不动 | 基础镜像 debian 源是 `deb.debian.org` | `Dockerfile` 里 `sed` 换成阿里云 Debian 源 |
| 拉 `python:3.11-slim` 慢或失败 | Docker Hub 内地直连不稳 | `bootstrap.sh` 写入 `registry-mirrors`（DaoCloud / 1panel / 南大） |
| arXiv 源一直 fail | 机房到 `export.arxiv.org:443` 被阻断（实测 25s 超时），容器内还会吃 429 | 第四源换成 **DOAJ**（开放获取期刊，免 key、1.8s）；海外机器可设 `ZHIHUI_ENABLE_ARXIV=1` 加回 arXiv |
| DBLP 返回 202 但解析不出数据 | DBLP 已上 Anubis 反爬，API 需跑 PoW 挑战 | 不用 DBLP |
| 服务器内部 curl 通、外网打不开 | **控制台防火墙**在云网络层拦截，和主机 iptables 是两套 | 控制台手动加一条 `TCP 8000` |

> 一句话记住：**主机 iptables 放行 ≠ 能访问**。阿里云/腾讯云的防火墙必须在控制台单独加，`bootstrap.sh` 只能管主机内部那一层。

之后从本文**第 3 节（SSH 登录）**开始照做，`bootstrap.sh` / `deploy.sh` 在阿里云 Ubuntu 上通用。`deploy.sh` 会自己识别阿里云/腾讯云主机，把 pip 源换成内网镜像（约 1 GB 依赖，走镜像 2~3 分钟，走 pypi.org 内地要 20 分钟以上）。

### 方案 B：本机 + Cloudflare 隧道（0 元、0 注册，应急用）

不用服务器、不用注册任何账号，把本机后端直接映射成公网地址：

```bash
scripts\public-demo\start-tunnel.bat        # Windows
bash scripts/public-demo/start-tunnel.sh    # macOS / Linux
```

脚本首次运行会自动下载 cloudflared（约 30 MB，走国内镜像；实测约 40 KB/s，慢网需等 10~20 分钟，只下一次），输出类似：

## 4. 放行端口（两个地方都要改，缺一不可）

这是部署失败率最高的一步。Oracle 有**两层**防火墙：

### 4.1 云控制台的安全列表

实例详情 → 点 **Subnet** → **Security Lists** → 默认安全列表 → **Add Ingress Rules**

| Source CIDR | IP Protocol | Destination Port Range |
| ---- | ---- | ---- |
| `0.0.0.0/0` | TCP | `80` |
| `0.0.0.0/0` | TCP | `443` |
| `0.0.0.0/0` | TCP | `8000`（不打算用 80 时再加） |

### 4.2 主机内部的 iptables

Oracle 的 Ubuntu 镜像自带一份 iptables 规则，**默认拒绝除 22 端口外的所有入站**。只改控制台的话，浏览器依然打不开。

一键脚本已自动处理（插入 ACCEPT、清掉兜底的 REJECT、持久化到 `/etc/iptables/rules.v4`）。手动等价命令：

```bash
sudo iptables -I INPUT 1 -p tcp --dport 80   -j ACCEPT
sudo iptables -I INPUT 1 -p tcp --dport 443  -j ACCEPT
sudo iptables -I INPUT 1 -p tcp --dport 8000 -j ACCEPT
# 去掉 Oracle 自带的兜底拒绝，避免 Docker 发布的端口被拦
sudo iptables -D FORWARD -j REJECT --reject-with icmp-host-prohibited 2>/dev/null
sudo apt install -y iptables-persistent
sudo netfilter-persistent save
```

> 排查口诀：`控制台通 + 主机通 = 能访问`。打不开时先在服务器上 `curl http://127.0.0.1:8000/api/health`——本机通但外网不通，问题一定在这两层防火墙。

## 5. 一键初始化服务器

把代码放上去（私有仓库建议用 Personal Access Token）：

```bash
sudo apt update && sudo apt install -y git
git clone https://<你的仓库地址> ~/zhihui
cd ~/zhihui
bash scripts/oracle/bootstrap.sh
```

脚本做四件事：

1. 内存小于 3.8 GB 时创建 2 GB swap（小机型构建防 OOM）
2. 安装 Docker + Compose 插件
3. 放行 80 / 443 / 8000，并持久化 iptables 规则
4. 打印后续命令

可调参数：

```bash
PORTS="80 8000" bash scripts/oracle/bootstrap.sh          # 只开指定端口
DOCKER_MIRROR=Aliyun bash scripts/oracle/bootstrap.sh     # Docker 走国内镜像
SWAP_SIZE=4G bash scripts/oracle/bootstrap.sh
```

> 脚本会把你加入 `docker` 组，**重新登录**（或 `newgrp docker`）后才免 sudo。

## 6. 一键部署

```bash
cd ~/zhihui
cp .env.example .env
nano .env            # 填 DEEPSEEK_API_KEY，Ctrl+O 保存，Ctrl+X 退出

bash scripts/oracle/deploy.sh
```

`deploy.sh` 会依次：检查 `.env` → `git pull` → `docker compose up -d --build` → 等健康检查 → 初始化演示账号 → 打印访问地址。

首次构建 5~15 分钟（ARM 机型要现场编译 chromadb，属正常现象）。

**想让地址更干净（不要 `:8000`）**：

```bash
PORT=80 bash scripts/oracle/deploy.sh
```

之后直接访问 `http://<公网IP>` 即可。

**构建太慢**（国内网络）：

```bash
PIP_INDEX_URL=https://pypi.tuna.tsinghua.edu.cn/simple bash scripts/oracle/deploy.sh
```

### 7.1 云防火墙没放行时：用隧道绕过（推荐兜底）

云平台的防火墙（阿里云轻量是独立的「防火墙」页签）在**网络层**拦包，主机里的 `iptables` 放行再多也没用。表现是：服务器内 `curl 127.0.0.1:8000` 返回 200，外面 `curl http://公网IP:8000` 直接超时。

如果一时进不去控制台，或者找不到放行入口，可以**从服务器主动向外建一条隧道**——出站连接不受入站防火墙限制：

```bash
# 在服务器上执行（脚本会自动下载 cloudflared、装成 systemd 服务、开机自启）
bash scripts/oracle/setup-tunnel.sh
```

脚本结束会打印：

```
TUNNEL_URL=https://xxxx-xxxx-xxxx.trycloudflare.com
```

这个地址**自带 HTTPS，任何人可访问，不需要备案、不需要开任何端口**，直接发给评委即可。

也可以用本地一条命令触发（脚本会上传并执行）：

```bash
python scripts/oracle/start-tunnel-remote.py <公网IP> <root密码>
```

查看当前地址：

```bash
ssh root@<公网IP> 'systemctl status zhihui-tunnel | head -5; grep -o "https://[a-z0-9-]*\.trycloudflare\.com" /var/log/zhihui-tunnel.log | tail -1'
```

需要注意的点：

| 事项 | 说明 |
| ---- | ---- |
| 地址会变 | Quick Tunnel 是临时隧道，**服务重启后域名会换**。演示前用上面的命令查一次当前地址 |
| 需要固定域名 | 用 `cloudflared tunnel login` + 自己的域名做 Named Tunnel（见 9.1），地址就固定了 |
| 国内访问 | `*.trycloudflare.com` 解析到 Cloudflare 边缘节点，国内可直连。**但如果本机开着 VPN/代理，可能反而连不上**，临时关掉代理或把它加入直连名单 |
| 限速 | 免费隧道有带宽限制，够页面演示，不适合大文件传输 |
| 云端 vs 本地 | 隧道在服务器上跑，电脑关机也不影响；本机的 `start-tunnel.bat` 是另一套（本机 demo 用） |

> 隧道只是绕路，**最优解仍然是让云防火墙放行 `TCP 8000`**（见第 4.1 节）。放行后 `http://公网IP:8000` 这条直连地址就永久可用，不必担心域名变化。

## 8. 接入 Oracle 对象存储（数据备份）

服务器数据全在 Docker 卷 `zhihui-data`（用户库、向量库、术语缓存、归档）。定期同步到免费对象存储，机器被回收或误删也能恢复。

### 8.1 创建存储桶

控制台 → **Storage → Buckets → Create Bucket**

| 项目 | 值 |
| ---- | ---- |
| Bucket Name | `zhihui-backups` |
| Default Storage Tier | Standard |
| Visibility | **Private** |

创建后记录三样东西：

1. **Namespace**（对象存储页面右上角，形如 `axxxxxxxxxxx`）
2. **Region**（如 `ap-tokyo-1`）
3. **Customer Secret Key**：右上角头像 → **Customer secret keys** → **Generate Secret Key**，记下 Access Key 与 Secret Key（**只显示一次**）

> ⚠️ 常见错误：用了「API Key」或「Auth Token」。S3 兼容接口必须用 **Customer Secret Key**。

### 8.2 配置 rclone

```bash
cd ~/zhihui
bash scripts/oracle/setup-rclone-oci.sh
```

按提示输入 Namespace / Region / Access Key / Secret Key / 桶名。脚本会安装 rclone、写入远端 `oci:`（端点 `https://<namespace>.compat.objectstorage.<region>.oraclecloud.com`）、测试连通性，并在需要时自动建桶。

也可一次填完（适合写进交付文档）：

```bash
OCI_NAMESPACE=axxxxx OCI_REGION=ap-tokyo-1 \
OCI_ACCESS_KEY=xxxx OCI_SECRET_KEY=xxxx OCI_BUCKET=zhihui-backups \
bash scripts/oracle/setup-rclone-oci.sh
```

### 8.3 备份与恢复

```bash
bash scripts/oracle/backup-to-oci.sh          # 备份（暂停服务 5~15 秒，数据最一致）
bash scripts/oracle/backup-to-oci.sh --hot    # 不停服务（适合定时任务）
KEEP=30 bash scripts/oracle/backup-to-oci.sh  # 云端保留 30 天

bash scripts/oracle/restore-from-oci.sh --list        # 看有哪些备份
bash scripts/oracle/restore-from-oci.sh               # 恢复最新一份
bash scripts/oracle/restore-from-oci.sh zhihui-data-20261115-030001.tar.gz
```

备份脚本：容器内打包 `/data` → 上传到 `oci:zhihui-backups/daily/YYYY/MM/` → 校验云端字节数 → 清理过期备份。
恢复脚本会**先自动打一份本地快照**（`.backup-before-restore-*.tar.gz`）再覆盖，避免手滑。

### 8.4 定时自动备份

```bash
crontab -e
```

加入（每天凌晨 3 点热备份）：

```
0 3 * * * cd $HOME/zhihui && bash scripts/oracle/backup-to-oci.sh --hot >> /var/log/zhihui-backup.log 2>&1
```

验证：

```bash
tail -20 /var/log/zhihui-backup.log
rclone ls oci:zhihui-backups/daily
```

### 8.5 额度与成本

20 GB 免费额度，单次备份压缩后只占几十 MB，保留 14 天约 1 GB，完全在免费范围内。**注意**：超额或超期后 OCI 可能按量计费，`KEEP` 不要设太大。

## 9. 绑定域名 + HTTPS（可选，强烈建议）

`http://IP` 属于不安全上下文，浏览器会禁用 Web Crypto API，导致「加密归档」功能失效。

### 9.1 有域名

1. 域名服务商添加 A 记录指向服务器公网 IP
2. 让容器只监听本机，由 Caddy 对外：

```bash
PORT=127.0.0.1:8000 bash scripts/oracle/deploy.sh
```

3. 安装 Caddy：

```bash
sudo apt install -y debian-keyring debian-archive-keyring apt-transport-https curl
curl -1sLf 'https://dl.cloudsmith.io/public/caddy/stable/gpg.key' | sudo gpg --dearmor -o /usr/share/keyrings/caddy-stable-archive-keyring.gpg
curl -1sLf 'https://dl.cloudsmith.io/public/caddy/stable/debian.deb.txt' | sudo tee /etc/apt/sources.list.d/caddy-stable.list
sudo apt update && sudo apt install -y caddy
```

4. 编辑 `/etc/caddy/Caddyfile`：

```
你的域名.com {
    reverse_proxy 127.0.0.1:8000
    encode gzip
}
```

```bash
sudo systemctl restart caddy
```

Caddy 会自动申请并续期 Let's Encrypt 证书（需 80/443 可访问）。

### 9.2 没有域名

保持 `http://IP` 演示，说明「加密归档需 HTTPS 环境」，其余功能不受影响。

## 11. 常见问题

| 现象 | 原因 | 解决 |
| ---- | ---- | ---- |
| 浏览器打不开，但服务器上 `curl 127.0.0.1:8000` 正常 | 防火墙没放行 | 第 4 节两层都要改；`sudo iptables -L INPUT -n` 看规则 |
| 页面能开但所有功能报错、请求卡住 | 前端 API 地址指向了自己电脑 | 已修复：前端自动用当前访问地址；若手动填过，清空设置里的「后端 API 地址」 |
| 构建时 `Killed` / 进程被杀 | 内存不足（1 GB 机型） | 跑 `bootstrap.sh` 建 swap；或改用 ARM A1 |
| 构建报 `chroma-hnswlib` 编译失败 | ARM 无预编译包，缺编译工具 | 用最新 Dockerfile（已含 build-essential）；`docker compose build --no-cache` |
| pip 下载极慢 / 超时 | 国内网络 | `PIP_INDEX_URL=https://pypi.tuna.tsinghua.edu.cn/simple` |
| `Out of host capacity` | A1 配额被占满 | 换可用域 / 重试 / 改用 E2.1.Micro |
| 容器反复重启 | `.env` 缺 Key 或 Key 无效 | `docker compose logs zhihui` 看报错 |
| 文献检索全部失败 | 服务器访问不了国际学术站点 | 换区域（首尔/东京），或 `curl -I https://api.openalex.org` 自查 |
| 备份报 `unexpected EOF` | 上传中断 | 重跑脚本；rclone 会自动重传 |
| 恢复后登录不上 | 备份早于账号创建 | 重新初始化演示账号：`docker compose exec zhihui python /app/scripts/init_demo_user.py` |

## 附录 A：手动部署（等价于一键脚本）

```bash
# 1. Docker
sudo apt update && sudo apt upgrade -y
curl -fsSL https://get.docker.com | sudo sh -s -- --mirror Aliyun
sudo usermod -aG docker $USER && newgrp docker

# 2. 端口（见 4.2）
sudo iptables -I INPUT 1 -p tcp --dport 8000 -j ACCEPT
sudo netfilter-persistent save

# 3. 代码与配置
git clone https://<仓库地址> ~/zhihui && cd ~/zhihui
cp .env.example .env && nano .env

# 4. 构建启动
docker compose up -d --build
docker compose ps
docker compose logs -f --tail=50

# 5. 演示账号
docker compose exec zhihui python /app/scripts/init_demo_user.py
```
